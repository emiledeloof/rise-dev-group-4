# .agy-rules.md

This file provides rules and architectural guidance for Antigravity (agy) and coding agents working with code in this repository.

## Commands & Environment

Requires the .NET 10 SDK and Docker Desktop. Solution file: `Rise.sln`.

```bash
# Setup
cp .env.example .env                                                                                                 # once; set POSTGRES_PASSWORD
dotnet user-secrets set "ConnectionStrings:DatabaseConnection" "Host=localhost;Port=5433;Database=rise;Username=rise;Password=<password>" --project src/Rise.Server

# Infrastructure
docker compose up -d                                                                                                 # PostgreSQL on localhost:5433
docker compose --profile tools up -d                                                                                 # + pgAdmin at http://localhost:5050

# Build & Test
dotnet build Rise.sln
dotnet test Rise.sln                                                                                                 # all tests
dotnet test tests/Rise.Services.Tests                                                                                # single project
dotnet test --filter "FullyQualifiedName~ProjectServiceShould.EditProjectWhenTechnicianIsTheSame"                    # single test

# Run application (serves API + Blazor WASM client at https://localhost:5001, Swagger at /swagger)
dotnet watch --non-interactive --project src/Rise.Server
dotnet run --project src/Rise.Server

# EF Core migrations (from repository root or src/ with dotnet-ef installed)
dotnet ef migrations add <Name> --startup-project src/Rise.Server --project src/Rise.Persistence
dotnet ef database update --startup-project src/Rise.Server --project src/Rise.Persistence
```

### Environment & Database Details
- In **Development**, the server automatically applies migrations and runs `DbSeeder` on startup.
- Database: PostgreSQL 17 in Docker (`docker-compose.yml`, db/user `rise`, password from git-ignored `.env`).
- Secrets: No credentials in Git. `appsettings.json` has an empty placeholder. Dev credentials come from .NET User Secrets (`ConnectionStrings:DatabaseConnection`).
- Seeded test users: `user@example.com`, `technician1@example.com`, `technician2@example.com`, `secretary@example.com`, `admin@example.com` (password: `A1b2C3!`).

## Architecture & Project Structure

The project follows Clean Architecture, DDD, and Vertical Slices:

- **`Rise.Domain`**: Core domain entities only.
  - No EF Core or ASP.NET references.
  - Depends only on `GuardClauses`, `Ardalis.Result`, and `Serilog`.
  - All entities inherit from `Entity` (provides `int Id`, `CreatedAt`, `UpdatedAt`, `IsDeleted`; entity equality by `Id`).
  - Invariants enforced in constructors/setters using `Guard.Against`.
  - Must include a parameterless constructor (can be private) for EF Core.
- **`Rise.Shared`**: Contracts shared between Client and Server.
  - Never references `Rise.Domain`.
  - Contains service interfaces (e.g., `IProductService`), request/response DTOs, and FluentValidation validators.
  - Follow the slice pattern: `<Feature>Request` (static partial class with nested `Create`, `Edit`, etc. and nested `Validator : AbstractValidator<T>`), `<Feature>Response`, `<Feature>Dto`, and `I<Feature>Service`.
  - List queries should use `QueryRequest.SkipTake` or `Cursor<T>`.
- **`Rise.Persistence`** (References `Rise.Domain`):
  - Contains `ApplicationDbContext` (`IdentityDbContext`), EF configurations, migrations, and triggers.
  - Entity configurations inherit `EntityConfiguration<T>` and call `base.Configure`. Auto-discovered via `ApplyConfigurationsFromAssembly`.
  - Table names use the singular entity name. String properties default to max length 4000; decimals to (18,2).
  - Triggers: `EntityBeforeSaveTrigger` automatically sets `CreatedAt`/`UpdatedAt` and intercepts deletes by setting `IsDeleted = true`. Do not set these fields manually.
- **`Rise.Services`** (References `Rise.Domain`, `Rise.Persistence`, `Rise.Shared`):
  - Implements the service interfaces from `Rise.Shared`.
  - Directly queries `ApplicationDbContext` (deliberately no repository abstraction).
  - Registered in `ServiceCollectionExtensions.AddApplicationServices`.
- **`Rise.Server`** (References all projects):
  - FastEndpoints host, Blazor WASM host (`UseBlazorFrameworkFiles` + fallback to `index.html`), and composition root.
  - Endpoints follow FastEndpoints pattern: `Endpoint<TRequest, Result<TResponse>>` delegating to services.
- **`Rise.Client`** (References `Rise.Shared` only):
  - Blazor WebAssembly frontend.
  - Contains its own client-side implementations of the Shared interfaces making API calls via `HttpClient`.
  - Code-behind pattern for Razor pages (`.razor` + `.razor.cs`).

## Cross-Cutting Conventions

1. **Results & Error Handling**:
   - Services and endpoints return `Ardalis.Result` / `Task<Result<T>>`.
   - FastEndpoints auto-send is disabled (`ep.DontAutoSendResponse()`).
   - `GlobalResponseSender` automatically maps `ResultStatus` to HTTP status codes (`NotFound` -> 404, `Invalid` -> 400, `Conflict` -> 409, `Error` -> 422).
   - Return appropriate `Result.*` from services instead of throwing exceptions or manipulating HTTP codes directly.
2. **Validation**:
   - Server discovers FluentValidation validators from `Rise.Shared`.
   - Client uses the exact same validators via `Blazored.FluentValidation`.
3. **Session & Current User**:
   - Services inject `ISessionContextProvider` (defined in `Services/Identity/IIdentityContextProvider.cs`, implemented by `HttpContextSessionProvider`).
   - Retrieve User ID using `User.GetUserId()` from `Shared/Identity/ClaimsPrincipalExtentions.cs`.
4. **Authentication**:
   - ASP.NET Identity with cookie authentication.
   - Client uses `CookieAuthenticationStateProvider` and `CookieHandler` on the `"SecureApi"` HttpClient.
   - Role constants are defined in `Shared/Identity/Roles.cs` (`AppRoles`), policies in `Policies.cs`.
5. **PostgreSQL Specifics**:
   - PostgreSQL provider is configured via `UseNpgsql`.
   - `DateTime` maps to `timestamp with time zone`. **Always store UTC** (`DateTime.UtcNow`, `DateTimeKind.Utc`). Npgsql rejects Local/Unspecified DateTime values.
   - String comparisons in queries (`Contains`, `==`) are case-sensitive.
6. **Logging**:
   - Structured logging with Serilog.
   - Mark sensitive DTO properties with Destructurama attributes to ensure masking in logs.

## Testing Guidelines

- Frameworks: **xUnit** + **Shouldly** + **NSubstitute**.
- Test class naming: `<Subject>Should`.
- Method naming: Describing behavior, e.g., `EditProjectWhenTechnicianIsTheSame` or `CreateGuestWhenValid`.
- **`Rise.Client.Tests`**: bUnit tests inheriting `BunitContext`, registering fakes (e.g., `FakeProductService`) and auth (`this.AddAuthorization().SetAuthorized(...)`).
- **`Rise.Services.Tests`**: Unit tests with EF InMemory provider (or mock context / fakes).
